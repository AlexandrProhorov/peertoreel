# M2.4 — стадия `visuals` (Pixabay) — промпт для новой сессии

Ты продолжаешь работу над **Kadence** в новой сессии. Сначала прочитай этот файл целиком,
затем `AGENTS.md`, `ROADMAP.md`, `ARCHITECTURE.md`, `docs/adr/0005-run-state-machine.md` и
`docs/adr/0007-web-data-layer.md`. Если в рабочем дереве есть незакоммиченные изменения
документации после закрытия M0 — не откатывай их.

## 1. Цель сессии

Реализовать **M2.4 — стадию `visuals`** end-to-end:

- из `VOICE_READY` поставить job `visuals`;
- для каждого beat сценария подобрать вертикальный стоковый клип/картинку через Pixabay;
- скачать только выбранные ассеты в S3, записать `visuals_json` и артефакты сцен;
- перевести run в `VISUALS_READY`;
- научить `render` собирать черновик из этих сцен вместо синтетического `testsrc2`;
- сохранить fallback на синтетический фон, если ассет не найден/скачать не удалось;
- обновить web (кнопка стадии, прогресс, гидрация), тесты и документацию.

**Не входит в сессию:** `topic-discovery`, `research`, `qc`, TikTok/publish, cost dashboard,
полный `provider_usage` ledger, музыка/ducking, сложные переходы между сценами, редизайн фронта.
Это отдельные milestone'ы.

## 2. Текущее состояние

M0 закрыт, M2 в работе. Сейчас работает цепочка:

```text
DRAFT (run создаётся с темой вручную)
  → RESEARCHING (переход вручную)
  → script       → SCRIPT_READY
  → voiceover    → VOICE_READY
  → render       → RENDERING → REVIEW
```

`render` пока использует синтетический фон `testsrc2`; стадии `visuals` нет.

## 3. Контракты: что обязательно изменить

В `packages/contracts/src/stages.ts`:

```ts
STAGE_QUEUES.visuals = 'visuals';
STAGE_JOB_NAMES.visuals = 'visuals';
STAGE_OF_QUEUE.visuals = 'visuals';
STAGE_REQUIRED_STATE.visuals = 'VOICE_READY';
STAGE_PRODUCED_STATE.visuals = 'VISUALS_READY';
STAGE_FOR_STATE.VOICE_READY = 'visuals';
stageQueueNameSchema = z.enum(['script', 'voiceover', 'visuals', 'render']);
```

Проверь, что `satisfies`/типы не дают забыть ни одну запись. Добавь тесты:

- `stageForProgress('VOICE_READY') === 'visuals'`;
- `STAGE_REQUIRED_STATE.visuals === 'VOICE_READY'`;
- `STAGE_PRODUCED_STATE.visuals === 'VISUALS_READY'`;
- `stageQueueNameSchema` принимает `visuals`;
- deterministic `stageJobId('visuals', runId)`.

Новые схемы лучше вынести в `packages/contracts/src/stock.ts` (или `visuals.ts`):

- `StockSearchRequest` / `StockAsset` — кандидат от провайдера;
- `StockProvider` — интерфейс порта (search/download), без vendor SDK;
- `VisualScene` — idx, beatIndex/part, text, visualDirection, startSec, endSec, asset;
- `VisualsArtifact` — `{ scenes: VisualScene[], durationSec, providerRequests, cacheHits }`;
- `visualSceneAssetSchema` — kind (`video`/`image`/`fallback`), objectKey, contentType,
  width/height (nullable), provider/id/author/pageUrl (nullable).

Не добавляй в контракты поля «на будущее» без текущего потребителя.

## 4. Провайдер Pixabay

Создай реализацию за портом, например `apps/worker/src/stock/pixabay.ts`.

Требования:

- `PIXABAY_API_KEY` в `apps/worker/src/config/env.ts` как **optional** (как LLM/TTS),
  в `.env.example` — placeholder. В процессоре — `requireProviderKey(...)` с понятной ошибкой.
- Ключ никогда не логируется, не попадает в кеш-ключи, артефакты и ошибки.
- Поиск:
  - видео: `https://pixabay.com/api/videos/`, `video_type=film`, `safesearch=true`,
    `per_page` 3–5, `page=1`;
  - картинки: `https://pixabay.com/api/`, `image_type=photo`, `orientation=vertical`,
    `safesearch=true`;
  - предпочитай вертикальные ассеты (`height > width`); горизонтальные можно кропнуть,
    но это осознанный fallback.
- `visualDirection` в сценарии на русском. Проверь актуальную документацию Pixabay:
  поддерживается ли `lang=ru`. Если качество поиска плохое, можно добавить один batched
  LLM-запрос на английские ключевые слова для всех beat'ов, но это отдельный provider call
  и его нужно кешировать; не делай скрытых повторных вызовов на каждый retry.
- Скачивай **только выбранный** ассет, не весь список результатов. Ограничь размер,
  проверь content-type, используй timeout и abort.
- Ошибки классифицируй:
  - 429/5xx/timeout — retryable (BullMQ attempts/backoff);
  - 400/401/403 — terminal, не ретраить;
  - нет результатов — не ошибка, fallback.
- Rate limit: Pixabay **100 req / 60 s** глобально. Стадия `visuals` должна иметь
  concurrency 1; перед каждым реальным HTTP-запросом вызывай limiter. Cache hit не тратит лимит.
- Cache: каждый результат поиска — на **24 часа**. Рекомендуется Redis с ключом
  `pixabay:search:<sha256(query|kind|lang|page|perPage)>` и TTL 86400; ключ API в hash не
  включай. Если добавляешь `ioredis` в worker — сделай его прямой dependency. Для тестов
  используй in-memory fake, не реальный Redis.
- Записывай `providerRequests` и `cacheHits` в `visuals_json` (реальные числа, не оценку).
  Полный `provider_usage` ledger — отдельная задача; Pixabay бесплатный, поэтому не выдумывай
  стоимость. Если решаешь добавить `provider_usage` сейчас — это отдельная миграция и ADR,
  не смешивай с visuals.

## 5. Планирование сцен и тайминги

Сценарий: `hook`, `beats[]`, `cta`. `visualDirection` есть только у beat'ов. Предлагаемый
минимальный план:

- hook использует visualDirection первого beat'а;
- каждый beat — своя сцена;
- cta использует visualDirection последнего beat'а;
- scene count = `1 + beats.length + 1` (или beats + hook/cta, если решишь иначе — обоснуй).

Реальные тайминги бери из `word_timings`, а не из `durationSec` сценария. Добавь чистый
helper (например, `apps/worker/src/visuals/beat-timings.ts`):

```ts
deriveBeatTimings(script: Script, words: DerivedWord[]): BeatTiming[]
```

- идёшь по словам и тексту hook/beats/cta по порядку;
- начало части — начало первого слова, конец — конец последнего;
- пунктуацию нормализуй, регистр не важен;
- если сопоставление не удалось — fallback: пропорционально `durationSec` сценария,
  масштабированный на реальную длину аудио (последний `endSec`);
- если `words` пуст — ошибка стадии.

Покрой helper тестами: точное совпадение, пунктуация/регистр, расхождение текста,
пустой alignment.

## 6. Стадия `visuals` (worker)

Файл: `apps/worker/src/stages/visuals.processor.ts`, регистрация в `main.ts`.

Логика:

1. `stageJobDataSchema.parse(job.data)`; `loadRun`.
2. Идемпотентность: если `run.state === 'VISUALS_READY'` — вернуть результат без работы;
   если не `VOICE_READY` — ошибка с понятным сообщением. Повторный запуск не должен плодить
   артефакты/объекты.
3. Загрузить `script_json` и `word_timings` из S3 (как voiceover/render).
4. `deriveBeatTimings`.
5. Для каждой сцены:
   - поиск через `StockProvider` (cache/limiter);
   - выбрать лучший ассет (вертикальный, достаточная длительность);
   - скачать и положить в S3;
   - если не нашли/скачать не удалось — `kind: 'fallback'` без файла или с синтетическим
     плейсхолдером; стадия не падает из-за одной сцены.
6. Сохранить `visuals_json` (**детерминированный object key**, например
   `runs/<runId>/visuals/visuals.json`) и артефакты сцен.
7. `job.updateProgress` по сценам (например, 10 + 70 * done/total, затем 90/100).
8. `transitionRun(db, runId, 'VISUALS_READY')`.
9. Вернуть `StageJobResult` (`stage: 'visuals'`, `state`, `artifacts`).

Идемпотентность артефактов:

- `saveArtifact` делает upsert по `object_key`; используй детерминированные ключи
  `runs/<runId>/visuals/scene-<idx>.<ext>` (или ключ без расширения + contentType в meta).
  При смене kind (video→image) удаляй старый объект через `deleteObject`, чтобы не оставлять
  мусор и дубли строк.
- `object_key` уникален; повторный запуск перезаписывает объект, а не создаёт новый.

`visuals_json` — рекомендуемый вариант для M2.4. Таблицу `scenes` не добавляй, пока у неё нет
потребителя (review UI); если решишь добавить — это отдельная миграция, обнови AGENTS и ADR.

## 7. Render: убрать синтетический фон

Сейчас `render.processor.ts` делает:

```text
testsrc2 → clip.mp4
renderDraft(clip.mp4, voiceover.mp3, subtitles.ass) → draft.mp4
```

Нужно:

1. Загрузить `visuals_json`; если его нет — сохранить текущий fallback `testsrc2` (не ломать
   старые run'ы).
2. Собрать визуальный трек `visuals.mp4` из сцен:
   - видео: `-i scene.mp4 -t <duration> -vf scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,setsar=1,fps=30`;
   - картинка: `-loop 1 -i scene.jpg -t <duration>` + тот же scale/crop;
   - fallback: `testsrc2`/цветной клип на длительность сцены;
   - склеить сегменты через concat demuxer, одинаковые codec/params.
3. Передать `visuals.mp4` в `renderDraft` вместо `clip.mp4`.
4. Если суммарная длина сцен меньше аудио — дотянуть последним кадром/фолбэком до
   `lastWordEnd + 1`; если больше — обрезать.
5. `meta.background` артефакта: `'visuals'` или `'fallback_testsrc2'`; добавь источники,
   если полезно для ревью.
6. FFmpeg — только массивы аргументов, без shell-строк и интерполяции пользовательского текста.
7. Временные файлы — в `tmpdir()/kadence-render/<runId>` и удалять в `finally`.

Вынеси сборку визуального трека в чистый helper (например, `media/visual-track.ts`) с
тестами на аргументы/план, чтобы не тащить логику в процессор.

## 10. Тесты

Обязательный минимум:

- contracts: новые stage mappings, schema `visuals`, `stageForProgress('VOICE_READY')`,
  `stageQueueNameSchema` принимает visuals;
- `beat-timings`: точное совпадение, пунктуация/регистр, fallback, пустой alignment;
- Pixabay provider: query params, выбор вертикального ассета, cache hit/miss, rate limiter,
  429 → retryable, 401/403 → terminal, malformed payload;
- visual planner: hook/beats/cta → scenes, fallback при отсутствии ассета;
- visual track builder: видео/картинка/fallback, длительности, FFmpeg args;
- processor idempotency, если получится с фейками deps: повторный запуск → один `visuals_json`,
  нет дублей артефактов; состояние `VISUALS_READY` → early return;
- render: использует `visuals.mp4`, при отсутствии visuals — `testsrc2`;
- web: stage button/title для visuals (если есть подходящий тест), ошибки/loading не ломаются.

Никаких реальных вызовов Pixabay/LLM/TTS/FFmpeg в unit-тестах. FFmpeg-хелперы тестируй на
построение аргументов, а не на запуск бинарника.

## 14. Открытые решения, которые нужно принять и зафиксировать

1. **Язык поиска.** `visualDirection` на русском: `lang=ru` Pixabay или отдельный
   LLM-перевод в EN-ключевые слова? Реши по фактическому качеству API; не делай лишних
   LLM-вызовов на каждый retry.
2. **Тайминги сцен.** Сопоставление слов из `word_timings` с hook/beats/cta; fallback —
   пропорционально плановым длительностям. Зафиксируй в ADR.
3. **`scenes` table vs `visuals_json`.** Для M2.4 рекомендуется `visuals_json` (нет consumer'а
   для таблицы). Если добавляешь таблицу — миграция + AGENTS + ADR.
4. **`provider_usage`.** Не добавляй полный ledger в эту сессию; запиши реальные
   `providerRequests`/`cacheHits` в `visuals_json` и оставь явный TODO/ADR.
5. **Fallback.** Одна сцена без ассета не должна валить всю стадию; полный провал всех
   ассетов — тоже fallback, а не FAILED, если аудио и субтитры целы. FAILED — только
   терминальные ошибки конфигурации/провайдера.
