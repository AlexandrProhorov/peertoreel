# 2026-11-15 — M3.6b.11: TTS как конфиг прогона

**Статус:** DONE · **Ветка:** `feat/m3-animated-factory`
**План:** нет отдельной карточки; шаг 1 из договорённости по надёжности
Цель

Дать оператору выбор TTS на прогоне (ElevenLabs или Google), чтобы исчерпанная квота была
понятной терминальной ошибкой, а не тихим ретраем или падением без объяснения.
Результат

- Contracts: `RUN_TTS_PROVIDERS`, `runSchema.ttsProvider`, `createRunRequestSchema.ttsProvider`
  (опционально), `defaultTtsProviderFor(mode)`; episode + `elevenlabs` отклоняется схемой с
  сообщением про отсутствие alignment-адаптера.
- DB: enum `run_tts_provider`, колонка `runs.tts_provider` (NOT NULL, default `elevenlabs`),
  миграция `apps/api/drizzle/0013_third_stick.sql`.
- API: прогон создаётся с провайдером (`request.ttsProvider ?? defaultTtsProviderFor(mode)`),
  `Run` отдаёт `ttsProvider`.
- Worker: `loadRun` читает провайдера; voiceover идёт по выбранному провайдеру. Google-ветка
  использует существующий `synthesizeWithGoogleTts` во временном каталоге и удаляет его.
- Ошибка квоты ElevenLabs (401/403 + `quota`) превращается в терминальную с текстом
  «переключите прогон на Google TTS и повторите voiceover».
- Web: селект TTS в форме создания (для episode принудительно Google), провайдер виден в шапке
  прогона.
- Тесты: contracts 197 (+1), worker 173 (+2), api 75 (+1), web 143 (+1); `pnpm check` зелёный.
Изменённые файлы

- `packages/contracts/src/run.ts` (+ спека), `packages/db/src/schema.ts`.
- `apps/api/src/runs/{runs.repository,runs.service,stages.service}.ts` (+ спеки), `drizzle/0013`.
- `apps/worker/src/stages/{transition,voiceover.processor}.ts` (+ спека), `storyboard/tts-fallback.ts`.
- `apps/web`: `runs-api.service.ts`, `runs-list-store.service.ts`, `runs-page`, `run-page`.
- `apps/worker/AGENTS.md`.
Решения

- Провайдер — данные прогона, не env: выбор виден в UI и переживает ретрай.
- Никакого тихого fallback: при квоте — терминальная ошибка с инструкцией.
- Episode-ветка остаётся на Google: у неё нет alignment-адаптера и это зафиксировано схемой.
Отклонения от плана

- Google-ветка переиспользует спайк-функцию `synthesizeWithGoogleTts`; её шапка обновлена,
  но качество таймингов остаётся приблизительным (аллокация по длине слов).
Не проверено

- Живой прогон voiceover через Google из очереди (нужны Redis/worker/браузер) — `Not verified`.
- Миграция на локальной БД не применена: Postgres не запущен; файл миграции сгенерирован и
  войдёт в CI/Testcontainers.
